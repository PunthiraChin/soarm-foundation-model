IMPLEMENTED / CODE MAP


Code Architecture


อ้างอิง commit bf14ea2 · ภาพข้างบนอธิบายแนวคิด ส่วนนี้อธิบายโค้ดที่มีจริง


สถานะ: โค้ดต่อครบสำหรับโจทย์โต๊ะติด marker พร้อมเริ่ม commissioning

ผ่าน 57/57 เทสต์ออฟไลน์บน Linux รวม OpenCV, LeRobot/Placo กับ URDF ที่ pin ไว้ และ API/เสียงผ่าน transport จำลอง. ยังไม่ได้ทดสอบบัญชี API จริง, ไมค์และลำโพงบน Mac, กล้องที่คาลิเบรตแล้ว หรือการเคลื่อนและหยุดของแขนจริง.
ยังไม่มีโค้ดสำหรับวัตถุไม่ติด marker หรือแบบจำลองการชนกับสิ่งของทั้งฉาก/ทุกจุดระหว่าง sample. GPT Live อาจพูดสถานะใหม่ด้วยคำอื่นหรือไม่พูด และแอปยืนยันไม่ได้ว่าผู้ใช้ได้ยิน ให้ถือสถานะบน CLI เป็นข้อมูลอ้างอิง.




01 / COMPOSE
app.py · profile.py · commission.py
โหมดจริงแยก preflight ตรวจไฟล์/bus/กล้อง, shadow ตรวจแผนช่วงแรกโดยไม่สั่งมอเตอร์, rehearse-hold ทดสอบการหยุดแบบจำกัด และ hardware สำหรับชุดที่ผ่าน commissioning. ส่วน scripts.dry_run ใช้ชุดจำลองและไม่ต้องใช้ key.


02 / VOICE
live.py · voice.py
GPT Live รับเสียงและคืน structured intent: เป้าหมายใหม่, เปลี่ยนเป้าหมาย หรือหยุด. ส่งสถานะและตัวเลือกเมื่อขอคำชี้แจง โดยให้ Live ตอบตามภาษาล่าสุดของผู้ใช้ และไม่รอเสียงใน control loop. การพูดแทรกกับคำสั่งหยุดแขนเป็นคนละเหตุการณ์.


03 / OBSERVE & PLAN
metric.py · astra_api.py
OpenCV อ่านกล้องบนและข้อมือพร้อม timestamp แยกกัน ใช้ marker และ calibration เพื่อหาตำแหน่งจริง. Astra รับภาพทั้งสองกับ pose/scene แล้วคืน decision และ Cartesian waypoint 2–4 จุดต่อช่วง. API ทำงานแยกจาก loop และมี timeout.


04 / DECIDE & TRACK
contracts.py · runtime.py
ตรวจ schema และปฏิเสธคำตอบที่ revision หรือ observation ไม่ตรง. ก่อนรับแผนที่มาช้าและก่อนเริ่มขยับ เช็กภาพและ encoder ใหม่ว่า scene ยังตรงกับแผน. หลัง grasp/ช่วงถือ/ก่อนปล่อย/หลังวาง ดูหลักฐานใหม่เพื่อไปต่อ ถาม หรือ retry.


05 / MOVE
motion.py · hardware.py
แปลง waypoint เป็น sample แล้วใช้ Placo/URDF ทำ IK. ตรวจขอบเขต, มุม, ขนาด step และ pose ก่อนส่งคำสั่ง. LeRobot Feetech bus ส่งค่า 5 แกนและ gripper แยก อ่านค่าจริงกลับ และแยก hold, register ACK และ encoder นิ่ง.


06 / OBSERVE THE RUN
telemetry.py
log สดและ JSONL เชื่อมด้วย run, revision, obs, slice. CLI แสดงไทยหรืออังกฤษ; JSONL เก็บรหัสกลาง. Live รับเฉพาะสถานะสั้น ไม่อ่าน log ทุกบรรทัด และไม่ส่งสถานะของงานเก่า. Log ปกติไม่มี key, เสียง, ภาพ หรือข้อความดิบ.








OPERATOR RUNBOOK / SO‑101


Lab Testing ทีละขั้น


เริ่มจากโหมดไม่ขยับแขน ผ่านทีละขั้นก่อนให้ของจริงเคลื่อน คู่มือนี้ใช้บน Mac ที่ต่อแขน ไม่ใช่บน cloud workspace.


    

  1. เตรียมเครื่องและรัน baseline โดยยังไม่ต่อมอเตอร์
    

    เปิด checkout เวอร์ชันที่มี docs/commissioning.md ใช้ venv Python 3.12 แยกจาก ACT/SmolVLA และ recording. Runtime pin LeRobot 0.4.4 ส่วนชุด recording เดิมใช้ 0.6.2: ไม่แก้ venv เดิม. ตรวจว่า Mac ติดตั้ง wheel และ PortAudio ได้ก่อน. ใช้ SO‑101 URDF revision ที่ pin ไว้ พร้อม meshes และ license แล้วตั้ง SOARM_TEST_URDF ไปยังไฟล์จริง.
    

    python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements-runtime.txt
python -m pip check
python -B -m unittest discover -s tests -v
python -B -m scripts.dry_run 'Pick up the blue cube and place it in the tray'
python -B -m scripts.dry_run --preview --trace
    

    ผ่านเมื่อ: dependency check + mock tests ผ่าน, mock จบที่ done, sample shadow เห็น shadow_preview และ simulated_writes=0. ถ้า native test ขึ้น skipped อย่านับว่าผ่าน. ติดตั้งไม่ได้ให้หยุดที่ขั้นนี้.
    

    2. 

  2. เลือก follower และตรวจ serial โดยไม่เปิด torque
    

    คัดลอก template เป็นไฟล์ส่วนตัว calibration/local/profile.json ตาม runbook. ตั้ง ID เป็น humanoice_follower_arm; ใช้ humanoice_follower_arm.json จาก รอบ recording ล่าสุด ใต้ calibration/robots/so_follower/ ใน cache เดิม ไม่ใช้ humanoice_follower.json ของ ACT หรือไฟล์ leader. ให้ calibration_file กับ SOARM_RECORDING_CALIBRATION ชี้ absolute path เดียวกัน. เลือกพอร์ตจากเครื่องตอนนี้ ไม่ใช้หมายเลข USB ประวัติเป็นหลักฐาน. คำสั่งด้านล่างใช้ file path ใน cache ปกติของ LeRobot; ถ้าเก็บไว้ที่อื่นให้แก้ตามไฟล์ recording ที่ยืนยันแล้ว.
    

    export SOARM_RECORDING_CALIBRATION="$HOME/.cache/huggingface/lerobot/calibration/robots/so_follower/humanoice_follower_arm.json"
python -m serial.tools.list_ports -v
python -B -m soarm_astra --mode preflight --stage files --profile calibration/local/profile.json
python -B -m soarm_astra --mode preflight --stage bus --profile calibration/local/profile.json
    

    ผ่านเมื่อ: พบ follower ที่ตรงกับบันทึก, ไฟล์และ URDF ผ่าน, อ่าน motor IDs/encoder ได้, ค่า register ตรงและ torque ปิดอยู่. ถ้าไม่ตรงหรือมี torque ให้หยุดและตรวจอุปกรณ์ ไม่บันทึก calibration ทับ และไม่ใช้ follower.connect(calibrate=False) แทน read-only.
    

    3. 

  3. ดูภาพสองกล้องก่อน แล้วคาลิเบรตกล้องกับแขน
    

    ค่าเริ่มต้นจากรอบ recording: top 0, wrist 1, 640 × 480 ที่ 30 FPS ที่ขอจากกล้อง ไม่ใช่ FPS ที่วัดแล้ว. เปิดภาพ preview บน Mac; กล้อง top ต้องเห็นโต๊ะ และ wrist ต้องเห็นปากคีบ. ใช้ path รูปที่ยังไม่มีไฟล์เพื่อไม่เขียนทับ.
    

    system_profiler SPCameraDataType
python -B -m soarm_astra --mode preflight --stage cameras --profile calibration/local/profile.json --preview-file calibration/local/roles.jpg
    

    วัด intrinsics/distortion และ transform ของ top→ฐาน กับ wrist→ปลายแขน. ใส่ ArUco DICT_4X4_50 ที่ก้อน ถาด จุดอ้างอิงแต่ละกล้อง และจุดที่ยืนยันมือว่าง. วัด tag offsets, TCP, ความสูงจับ/ปล่อย, ขอบเขตโต๊ะ, มุม/ข้อจำกัด และ latency ตาม runbook. ไฟล์ motor calibration ไม่ได้มีค่าพวกนี้.
    

    python -B -m soarm_astra --mode preflight --stage full --profile calibration/local/profile.json
    

    ผ่านเมื่อ: ภาพ/บทบาทตรง, mount และ tag ตรง, การอ่านวัดผ่าน freshness/skew โดยไม่มี motor writes. ตรวจเทียบ FK กับ TCP ที่วัดจริงหลายท่า. ถ้าภาพสลับ/บัง มุมไม่ตรง หรือ pose เลื่อน ให้แก้ก่อนเดินต่อ.
    

    4. 

  4. ทดสอบ Astra และ GPT Live จริง โดยยังไม่ขยับแขน
    

    ตั้ง OPENAI_API_KEY ใน secret หรือ environment ของเครื่อง ไม่ใส่ Git/แชต. ขั้นนี้เรียก Astra จริงทั้งสองคำสั่งและส่งภาพจริงจากกล้อง; คำสั่งที่สองเปิด GPT Live ส่งเสียงจากไมค์ด้วย. ทำให้มุมกล้องไม่ติดคนหรือข้อมูลที่ไม่ต้องการส่ง.
    

    python -B -m soarm_astra --mode shadow --profile calibration/local/profile.json --typed 'Pick up the blue cube and place it in the tray'
python -B -m soarm_astra --mode shadow --profile calibration/local/profile.json
    

    ผ่านเมื่อ: ได้คำตอบ planner ถูก schema และแผนช่วงแรกผ่าน IK, สั่งภาษาไทยและอังกฤษทีละรอบแล้วเกิด typed intent ตรงกับคำสั่ง, ได้ยินสถานะจากลำโพงจริง, log เชื่อมแต่ละช่วงได้, และไม่มี motor writes. ลองโจทย์กำกวมเพื่อเช็กว่าระบบถามได้จริง. ถ้า timeout, สิทธิ์โมเดลไม่ผ่าน หรือเสียงไม่ตอบ ให้แก้ API แยกจากการเปิด motion.
    

    5. 

  5. ทดสอบการหยุดด้วยการขยับจำกัด ไม่เรียก API
    

    ทำหลัง full preflight เท่านั้น: รองรับแขนเปล่า ให้คนที่สองอยู่ที่จุดตัดกำลัง และตรวจเส้นทางข้อมือสั้น ๆ ว่าไม่มีสิ่งกีดขวาง. ปิด commissioned ไว้และเปิด allow_hold_rehearsal ชั่วคราวเฉพาะในไฟล์ส่วนตัว. คำสั่งนี้เปิด torque และขยับ wrist roll +0.5° หนึ่งครั้ง โดยไม่มีการสั่งจากเสียงหรือ planner.
    

    python -B -m soarm_astra --mode rehearse-hold --profile calibration/local/profile.json --enable-motion --trace
    

    ผ่านเมื่อ: encoder ขยับจริงในทิศที่คาด ระบบยืนยันทั้ง register echo และ encoder นิ่ง แล้วทำตามขั้นตอนปิดเครื่องของแล็บ. หากผิดทิศ จับสัญญาณหยุดไม่ได้ หรือขาดคนเฝ้าจุดตัดกำลัง ให้หยุดก่อน demo. ปิด allow_hold_rehearsal เมื่อเสร็จ.
    

    6. 

  6. ทดสอบหยิบวางจริงโดยมีผู้ปฏิบัติงานเฝ้าแขน
    

    จัดพื้นที่ว่าง รองรับแขนและโหลด และมีวิธีตัดกำลังจริงเข้าถึงได้ทันที. ทวน watchdog, stop file และข้อยกเว้น collision ทีละคู่จากคู่มือ. หลังทดสอบการหยุด ให้เริ่มกับของเบาและท่าที่ตรวจสอบแล้ว. ตั้ง commissioned: true เฉพาะหลังผู้ปฏิบัติงานตรวจตาม runbook. คำสั่งใช้ GPT Live เป็นค่าเริ่มต้น; เติม --typed ตาม README สำหรับรับคำสั่งข้อความ.
    

    mkdir -p runs
python -B -m soarm_astra --mode hardware --profile calibration/local/profile.json --enable-motion --jsonl runs/supervised.jsonl
    

    คำสั่งนี้ขยับแขนได้: ถ้ามีการเคลื่อนที่ไม่ตรงแผน ให้ใช้วิธีหยุดจริงของแล็บ ไม่รอสั่งเสียง. ในการทดสอบ local hold ใช้ touch "$SOARM_STOP_PATH" เฉพาะเมื่อตั้งตัวแปรให้ตรงกับ absolute stop_file ของ profile; ต้องตรวจทั้ง stop_ack และ settled, ไม่ใช่ดูแค่ ACK. ตอนปิดโปรแกรมอย่าคิดว่า torque ถูกปิดเอง.
    

    ผ่านเมื่อ: encoder ตามคำสั่งได้จริงและหยุดนิ่ง, หยิบและวางจากคำสั่งไทยและอังกฤษในฉากใหม่ได้, เคสเปลี่ยนงานไม่ปล่อยของกลางอากาศและไม่ส่งคำสั่งงานเก่าหลัง ACK. เก็บผลแยกครั้งแรก/หลังแก้/มีคนช่วย.
    7. 



อ่าน log เพื่อตัดสินใจว่าจะเช็กตรงไหน

sensor_stale → เช็กภาพ/encoder และเวลาวัด · scene_moved_or_uncertain → เช็ก marker, การบัง หรือวัตถุเปลี่ยนตำแหน่ง · planner_error → เช็ก API · path_rejected → เช็ก IK, limits และ pose · tracking_timeout → ดู encoder และผลหยุดจริง.


เมื่อเปลี่ยนงาน ให้ดู last_old_write → hold_sent → stop_ack → settled → checkpoint → first_new_write. ถ้าขาด ACK/settled ให้หยุดตรวจ ไม่เริ่มงานใหม่. ใช้ชื่อ JSONL ใหม่ต่อรอบ; log อยู่ในเครื่อง และอย่าแนบ preview/calibration กับ public repo.
